# FeranoCar — frontend

The agent panel and the admin panel, built on the design Erfan and Mehdi approved.

## No build step

Plain ES modules. Serve `index.html` from any static server and it runs — no bundler, no
`npm install` needed to read the code, no dependency tree to audit.

That is a deliberate choice rather than a shortcut. The stated priority for this project is
that a developer hired later can understand it quickly, and the shortest path there is code
that runs as written. It also means nginx serves files and nothing else: no Node process for
the frontend to keep alive, restart, or patch.

The cost is no framework conveniences. The approved mockup was already written this way and
covered the same twenty-odd screens, so the ceiling is known rather than guessed.

## Running it locally

```bash
cd ../backend && npm run dev          # API on :3000
node tests/dev-server.js              # static files + /api proxy on :5173
```

`tests/dev-server.js` exists only for local work — in production nginx does both jobs.

## Layout

```
index.html
src/
  main.js            boot, render loop, one delegated click handler
  router.js          hash routing
  session.js         who is signed in, and what they are entitled to
  constants.js       brand, and limits mirrored from the server
  api/               client.js (the only fetch) + index.js (endpoints)
  state/store.js     small, deliberate application state
  ui/                html.js, format.js, shell.js, modal.js, feedback.js
  pages/agent/       dashboard, search, listings, account
  pages/admin/       index.js, catalog.js
```

## Three rules worth knowing before changing anything

**1. `ui/html.js` escapes by default.** Every value interpolated into markup is escaped
unless wrapped in `raw()`. The mockup escaped by calling `esc()` at each site, which works
until somebody forgets one — and a listing description reading `<img src=x onerror=…>` then
runs as script in every viewer's session. Inverting the default turns a mistake into a
visible `raw()` in the diff instead of an invisible absence.

**2. Behaviour attaches through `data-` attributes, never inline `onclick`.** An inline
handler built by string interpolation is a script-injection point, and the interpolated
values here are things users typed. `main.js` holds one delegated listener and one list of
handled keys; add a key there when you add an action.

**3. Nothing here decides what a user is allowed to do.** The permission table in
`state/store.js` decides what to *show* — hiding a button the server would refuse is
courtesy. The server checks every request regardless, because this code runs on the viewer's
machine and cannot be trusted.

## Masking

There is no masking logic in this codebase, and that is the point: the API never sends a
phone number the viewer has not revealed, so there is nothing on this side to hide. What the
interface does is make the cost visible before the click — the reveal button confirms first
and says how much of the daily allowance is left, because a button that silently spends one
of thirty views is a button people learn to fear.

`tests/smoke.mjs` walks the whole document and fails if a phone number appears outside a card
the agent actually revealed.

## Tests

```bash
npm i playwright     # once
AGENT_USER=… AGENT_PASS=… ADMIN_USER=… ADMIN_PASS=… node tests/smoke.mjs
```

Fifteen steps through both panels against a live API. It found the bug that mattered: the
delegated click handler used a hand-written CSS selector that was one entry short, so every
admin button was silently dead. Unit tests would not have caught it — a handler that matches
nothing throws nothing.

`screens/` holds a screenshot of each page, regenerated by the same tooling.

## Fonts and assets

Vazirmatn is served from `/assets`, not from Google Fonts. A CDN request leaves the country,
so on a day when the international link is disrupted the panel would fall back to a system
font for users whose own server is perfectly reachable — and every such request tells a third
party who is using this system and when.
