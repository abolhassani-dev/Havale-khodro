# چک‌لیست تهیه‌ی زیرساخت

کارهایی که باید انجام شود تا سامانه قابل استقرار باشد. کدنویسی منتظر هیچ‌کدام از این‌ها نیست —
سرور فقط در گام استقرار لازم می‌شود، پس این دو کار موازی پیش می‌روند.

---

## الف) الان لازم است

### ۱. سرور

| مورد | مشخصات |
|---|---|
| پردازنده | ۴ هسته |
| رم | ۸ گیگابایت |
| دیسک | ۱۰۰ گیگابایت NVMe |
| سیستم‌عامل | Ubuntu 24.04 LTS (یا 22.04) |
| موقعیت | ایران |
| دسترسی | SSH با کلید، نه رمز |

ارائه‌دهنده‌های متداول داخلی: ابر آروان، پارس‌پک، ایران‌سرور. قیمت‌ها را موقع خرید بگیرید.

**نکته:** IP ثابت بگیرید و پورت‌های ۲۲، ۸۰ و ۴۴۳ باز باشد. بقیه بسته.

### ۲. دامنه

- **اسم نهایی: FeranoCar / فرانوکار**
- ✅ `feranocar.com` خریداری شد
- ⬜ `feranocar.ir` — به آینده موکول شد. احراز هویت ایرنیک زمان‌بر است و مسیر کار را
  متوقف نمی‌کند.
- ⬜ هندل‌های شبکه‌های اجتماعی — همه آزاد بودند و گرفتنشان رایگان است

### ۳. سرویس ابری جلوی سایت — **فعلاً لازم نیست**

این سامانه هیچ صفحه‌ی عمومی ندارد؛ همه چیز پشت لاگین است. پس CDN چیزی برای کش کردن ندارد
و سطح حمله بسیار کوچک‌تر از یک بازارگاه عمومی است. تصمیمش را بعد از لانچ بگیرید، وقتی
ترافیک واقعی را دیدید.

**نکته‌ی مهم درباره‌ی کلادفلیر:** برای DNS بله (رایگان و بی‌ضرر)، ولی **ابر نارنجی را روی
سرور ایران روشن نکنید** — کلادفلیر داخل ایران PoP ندارد، پس ترافیک کاربر تهرانی از دبی
رد می‌شود و برمی‌گردد. هم تأخیر چند برابر می‌شود، هم با اختلال لینک بین‌الملل سایت
می‌خوابد در حالی که سرورش سالم است. جزئیات در `staging.md` بخش ۷.

### ۴. پنل پیامک

- پنل + **خط خدماتی** (خط تبلیغاتی برای کد ورود کار نمی‌کند)
- کاوه‌نگار، ملی پیامک یا مشابه
- لازم برای: کد ورود دو عاملی، بازیابی رمز، هشدار بسته شدن آگهی

### ۵. فضای بکاپ

فضای ذخیره‌سازی **جدا از سرور اصلی**. بکاپی که روی همان سرور باشد، با از دست رفتن سرور از بین
می‌رود — یعنی بکاپ نیست.

### ۶. قوانین و شرایط استفاده

برای تعلیق حساب و برخورد با تخلف پشتوانه لازم دارید. متن اولیه را می‌توانم بنویسم؛
بازبینی حقوقی با شما.

## 📌 نت — تصمیم‌های به‌تعویق‌افتاده تا روز لانچ

این‌ها **دانسته** تا روز لانچ عقب افتاده‌اند. یعنی اگر `preflight.sh` درباره‌شان هشدار
داد، خبرِ تازه‌ای نیست — ولی روز لانچ باید تک‌تک انجام شوند.

| مورد | وضعیت فعلی | روز لانچ |
|---|---|---|
| بکاپ بیرون از سرور | فقط روی خود سرور نگه داشته می‌شود | فضای ابری (آروان/لیارا) تنظیم و **یک بار تست** شود |
| حساب‌های نمایشی | فعال‌اند، رمزشان دستی عوض شده | حذف شوند |
| `SEED_DEMO` / `ALLOW_DEMO_SEED` | `true` | هر دو `false` |
| دیتابیس | داده‌ی نمایشی دارد | **فرش شود** — از صفر، بدون داده‌ی آزمایشی |
| `DATA_ENCRYPTION_KEY` | خالی | تولید شود (قبل از ورود اولین شماره‌ی واقعی) |

**ترتیبش مهم است.** کلید رمزنگاری باید *قبل از* اولین داده‌ی واقعی ساخته شود، وگرنه
باید بعداً backfill کنید؛ و فرش کردن دیتابیس باید *بعد از* حذف دموها باشد تا چیزی
از آن‌ها باقی نماند. یعنی:

```
۱. بکاپ نهایی از وضعیت فعلی (برای احتیاط)
۲. DATA_ENCRYPTION_KEY را بسازید
۳. SEED_DEMO=false و ALLOW_DEMO_SEED=false
۴. دیتابیس را فرش کنید
۵. مدیر کل را بسازید (npm run seed)
۶. مقصد بکاپ بیرونی را تنظیم و تست کنید
۷. ./deploy/preflight.sh — باید صفر ✗ بدهد
```

> چرا این‌جا نوشته شده و نه در جایی موقت: چون تنها چیزی که این‌ها را از «تصمیم» به
> «فراموش‌شده» تبدیل می‌کند، نوشته‌نشدنشان است.

## 💾 بکاپ چه چیزهایی را می‌گیرد

`deploy/backup.sh` یک آرشیو **خودکفا** می‌سازد — برای بازگردانی نه به گیت‌هاب نیاز
است، نه به اینترنت:

| پوشه | محتوا |
|---|---|
| `database/` | دامپ کامل SQL |
| `config/` | `.env` (شامل کلید رمزنگاری)، `docker-compose.yml`، پیکربندی nginx، کرون‌ها |
| `certs/` | گواهی TLS — صدور دوباره‌اش هفته‌ای پنج بار محدود است |
| `source/` | **کد برنامه**، دقیقاً همان نسخه‌ای که در حال اجرا بود |
| `system/` | سیستم‌عامل، بسته‌ها، فایروال، وضعیت داکر، دیسک |
| `MANIFEST.txt` | فهرست محتوا و اندازه‌ها — بدون باز کردن آرشیو خوانده می‌شود |
| `RESTORE.md` | مراحل بازگردانی، قدم به قدم |

سه لایه‌ی مستقل: ساعتی (۴۸ نسخه)، روزانه (۳۰)، هفتگی (۱۲). چرخش هر لایه جداست، پس
بکاپ ساعتی هیچ‌وقت نمی‌تواند نسخه‌ی روزانه را از بین ببرد.

ماهی یک بار: `./deploy/verify-backup.sh` — آرشیو را در یک دیتابیس موقت بازمی‌گرداند و
می‌شمارد چه چیزی برگشت. دیتابیس اصلی دست نمی‌خورد.

## ⚠️ درباره‌ی رمزها و کلیدها

**کلید API پیامک، رمز سرور و هیچ راز دیگری را در چت نفرستید.**

این‌ها مستقیم روی سرور در فایل `.env` قرار می‌گیرند. من ساختار و راهنمای پر کردنش را می‌دهم؛
مقدارها را خودتان جای می‌گذارید. رازی که در یک تاریخچه‌ی چت بنویسید، در همان تاریخچه می‌ماند.
