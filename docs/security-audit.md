# بازبینی امنیتی — شهریور ۱۴۰۵

یک بازبینی کامل از بک‌اند، فرانت‌اند، پایگاه داده و زیرساخت دیپلوی، به روش
«مثل مهاجم بخوان، مثل نگهبان ببند». هر یافته یا **همان روز بسته شد** و یک تست
برایش نوشته شد (`backend/tests/e2e/hardening.test.js`)، یا این‌جا با دلیل و
پیشنهاد ثبت شده تا مالک تصمیم بگیرد.

**تکرار این بررسی:** `node security/audit.js` (کد) و
`node security/audit.js --live https://feranocar.com --user … --pass '…'` (سرور
زنده). گزارش کامل در `security/last-report.json` نوشته می‌شود و در مخزن نیست.

هیچ راز، رمز یا کلیدی در مخزن یا تاریخچه‌ی گیت نیست (`git ls-files` فقط
`.env.example`ها را دارد؛ تاریخچه هم گشته شد).

**وابستگی‌ها — یک مورد معوق:** `npm audit` دو هشدار *متوسط* روی `qs` (وابستگی
express) می‌دهد؛ رفعش یک override به `qs >= 6.16.0` در `backend/package.json`
است. این پین یک بار اعمال شد و در همان روز برداشته شد، چون تغییر
`package-lock.json` باعث می‌شود Docker همه‌ی بسته‌ها را دوباره دانلود کند و
مخزن‌های npm از سرور در دسترس نبودند. **کار باز:** روزی که
`curl https://registry.npmmirror.com/express` از سرور `200` داد، این را اضافه
کنید و دیپلوی کنید:

```json
"overrides": { "qs": ">=6.16.0" }
```

و بعد `npm install --package-lock-only` تا lockfile به‌روز شود.

## ۳. چه چیزی باز ماند — و چرا

این‌ها تصمیم مالک‌اند، نه فراموشی. هر کدام با هزینه و پیشنهاد.

### C1 — بکاپ، کلید رمزنگاری را کنار داده‌ها می‌گذارد (بحرانی، وابسته)

`backup.sh` فایل `.env` (که `DATA_ENCRYPTION_KEY`, `POSTGRES_PASSWORD`,
`SESSION_SECRET` را دارد) را در همان آرشیوی می‌گذارد که دامپ دیتابیس هست. تا
وقتی رمزنگاری خاموش است (تصمیم فعلی مالک) این فرقی نمی‌کند — دامپ به هر حال
خواناست. **روزی که کلید فعال شد**، این باید عوض شود:

- آرشیو قبل از خروج از سرور با `age` یا `gpg --symmetric` رمز شود و کلیدش
  جای دیگری بماند؛ یا
- `.env` در فایل جدا و با مقصد جدا از دامپ ذخیره شود.

`launch-checklist.md` این را کنار «فعال کردن کلید» گذاشته تا یکی بدون دیگری
انجام نشود.

### C2 — پنل دیتابیس (Adminer) روی اینترنت (کاهش‌یافته)

پورت ۸۴۴۳ روی همه‌ی آدرس‌ها باز است — پشت TLS، Basic Auth، رمز خودِ دیتابیس،
`limit_req` و حالا `limit_conn`. قبل از اجرای `enable-ssl.sh` هر دو رمز روی
HTTP ساده می‌رفتند؛ روی سرور فعلی TLS فعال است. پیشنهاد امن‌تر که کارِ مالک را
عوض می‌کند و به همین دلیل اعمال نشد:

```yaml
# docker-compose.yml → adminer: ports: ['127.0.0.1:8443:8443']
# و ورود با تونل:  ssh -L 8443:127.0.0.1:8443 root@server
```

اگر آدرس اینترنت مالک ثابت شد، گزینه‌ی `allow/deny` در `adminer.conf` همین
نتیجه را بدون تونل می‌دهد.

### C3 — دیپلوی از شاخه‌ی بدون امضا (مهم، فرایندی)

`update.sh` با root کد شاخه را `reset --hard` می‌کند و می‌سازد؛ هیچ امضا یا
پینی روی commit نیست. کاهش‌دهنده‌ی واقعی: **دیپلوی خودکار وجود ندارد** — همیشه
یک انسان اجرا می‌کند و `update.sh` قبل از build، commitهای تازه را چاپ می‌کند.
برای بستن کامل: تگ امضاشده (`git verify-tag`) و branch protection روی GitHub.
پیشنهاد می‌شود پیش از استخدام توسعه‌دهنده‌ی دوم انجام شود.

### M — نگه‌داشتن `ip` روی رکورد نمایش مشخصات برای همیشه

ردیف `ContactReveal` سند خریدِ سهمیه است و عمداً پاک نمی‌شود. ستون `ip` آن
می‌تواند بعد از یک سال null شود بدون آن‌که سند بی‌ارزش شود. تغییر کوچکی است؛
چون قاعده‌ی «هرگز پاک نشود» تصمیم محصول بود، این‌جا فقط پیشنهاد است.

### L — چند مورد کوچک، ثبت‌شده

- `onDelete: Cascade` روی `ContactReveal.viewer` و `ViolationReport.reporter`:
  حساب هرگز حذف نمی‌شود (قاعده‌ی محصول)، پس فعال نیست؛ اگر روزی «حذف حساب»
  ساخته شد، به `Restrict` تغییر کند.
- `certbot/certbot:latest` بدون پین نسخه — تغییرش نیازمند pull از میرور است؛
  در دیپلوی بعدی که میرور پایدار بود، به تگ نسخه‌دار پین شود.
- `SESSION_SECRET` الزامی است ولی هیچ کوکی امضاشده‌ای وجود ندارد (نشست در
  دیتابیس است). بی‌ضرر؛ نگه داشته شد تا `.env`های موجود نشکنند.
- نشانه‌ی سایت روی صفحه‌ی خطای مستقل (`error.html`) سیاست CSP جداگانه ندارد —
  از nginx می‌آید و کافی است.

## ۴. چه چیزی بررسی شد و سالم بود

برای این‌که بازبینی بعدی دوباره از صفر شروع نکند:

- **تزریق SQL** — هیچ `$queryRawUnsafe`؛ تنها raw، قفل مشورتی با پارامتر بایند
  شده و `SELECT 1` سلامت است.
- **XSS** — هر ۸۷ کاربرد `raw()` طبقه‌بندی شد: صفت بولی، sentinel خالی، markup
  ثابت، یا literal با ورودی ثابت. `content/guide.js` ماژول ایستاست. هیچ
  `eval`, `document.write`, `srcdoc`, event attribute.
- **آلودگی پروتوتایپ / mass assignment** — Joi با `stripUnknown` روی body,
  params, query؛ `Object.fromEntries` مسیرهای امن.
- **ریدایرکت باز** — همه‌ی ناوبری‌ها `location.hash` هستند.
- **ذخیره در مرورگر** — صفر `localStorage`/`document.cookie`؛ توکن هرگز به JS
  نمی‌رسد؛ صفر `console.log`.
- **پنهان‌سازی تماس** — سرور تصمیم می‌گیرد؛ کارت عمومی هیچ فیلد تایپی ندارد؛
  عکس‌ها پشت مجوز؛ `textLeak.test.js` هر ستون متنی را خودش می‌یابد.
- **مسیرهای مدیریت** — هر مجوز پنل، `requirePermission` هم‌نام روی سرور دارد.
- **X-Forwarded-For** — nginx append می‌کند و `trust proxy 1` آخرین را می‌خواند؛
  جعل ممکن نیست. اگر روزی CDN جلو آمد، همان کامیت باید `2` کند.
- **کوکی نشست** — `httpOnly`, `sameSite=strict`, `secure` از روی اتصال.
- **بسته‌ها** — multer 2، express 4.22، helmet 7، prisma 5؛ `npm audit` صفر.
- **کانتینرها** — فقط nginx پورت دارد؛ DB و API و Adminer فقط داخل شبکه‌ی
  compose؛ preflight ۵۴۳۲ و ۳۰۰۰ را در ufw **بسته** می‌خواهد.
- **بکاپ** — دامپ با نشانه‌ی پایان، آرشیو self-contained، `verify-backup.sh`
  واقعاً restore می‌کند.

## ۵. کارهای بعد از دیپلوی این تغییرات

1. `./deploy/update.sh` (دو بار — خودش را بازنویسی می‌کند). خروجی باید
   «refreshing the HTTPS configuration» را نشان دهد.
2. `./deploy/preflight.sh` — بند «سربرگ‌های امنیتی روی /src/» باید سبز شود.
3. `curl -I https://feranocar.com/tests/smoke.mjs` → ۴۰۴.
4. `node security/audit.js --live …` از داخل کانتینر (دستور در
   `deployment.md`) — انتظار: ۰ بحرانی، ۰ مهم.
5. با فعال شدن رمزنگاری (هر وقت مالک تصمیم گرفت): ابتدا کلید، بعد
   `docker compose exec api node scripts/encrypt-existing.js`، بعد رمز کردن
   بکاپ (C1).
