# فصل ۲ — معماری

**در این فصل:** اجزای سامانه، مسیر یک درخواست از مرورگر تا دیتابیس، و دو الگویی
که کل کد روی آن‌ها بنا شده: «هسته + ماژول بازار» در سرور و «رندر از حالت» در پنل.

---

## ۲.۱ اجزا

```
                     ┌──────────────────────── سرور (Docker Compose) ────────────────────────┐
 مرورگر ──HTTPS──▶  │ nginx (web)                                                            │
                     │  ├─ /            فایل‌های ثابت frontend/  (بدون build)                  │
                     │  ├─ /api/v1/    ─proxy─▶  api (Node 20 + Express 4)  ─▶  db (Postgres 16)│
                     │  └─ :8443       ─proxy─▶  adminer (پنل دیتابیس، پشت Basic Auth)          │
                     │                                                                          │
                     │ کرونِ هاست ─▶ docker compose run api node src/jobs/nightly.js            │
                     │             ─▶ docker compose run api node src/jobs/car-prices.js        │
                     └──────────────────────────────────────────────────────────────────────────┘
```

| جزء | فناوری | نکته |
|---|---|---|
| فرانت‌اند | HTML + CSS + ES Modules خام، **بدون فریم‌ورک و بدون build** | یک `index.html`، ۳۰ ماژول، فونت محلی. nginx مستقیم سرو می‌کند |
| بک‌اند | Node 20، Express 4، Prisma 5، Joi، bcryptjs، multer 2، helmet | CommonJS. یک پروسه (یا چند worker با `CLUSTER_WORKERS`) |
| پایگاه داده | PostgreSQL 16 | ۳۱ مدل، مایگریشن با Prisma |
| کارهای زمان‌بندی‌شده | **کرونِ هاست** که هر بار یک کانتینر تازه اجرا می‌کند | هیچ `setInterval`ای در سرور نیست |
| سرو و TLS | nginx 1.27 + certbot (Let's Encrypt) | فایل‌های TLS روی سرور تولید می‌شوند |
| پشتیبان‌گیری، دیده‌بانی، هشدار | اسکریپت‌های bash در `deploy/` + ربات بله/تلگرام | فصل ۸ |

## ۲.۲ مسیر یک درخواست

```
GET https://feranocar.com/#search           (پنل — فایل ثابت، router هش را می‌خواند)
  └─ fetch /api/v1/havales?page=1           (client.js — تنها جایی که fetch هست)

nginx  ─▶  location /api/  ─▶  api:3000

Express (app.js) — به همین ترتیب:
  blockedIp        آدرس بسته‌شده؟ همین‌جا تمام
  helmet, cors
  json/urlencoded  سقف بدنه ۱ مگابایت
  cookieParser
  requestId, requestContext   شناسه و آدرس درخواست برای همه‌ی لایه‌های پایین
  morgan, slowRequest         لاگ دسترسی؛ کندتر از ۱۲۰۰ms → لاگ فنی
  threatDetect                الگوی حمله؟ فقط *ثبت* می‌کند، هرگز نمی‌بندد
  rateLimiter                 سهمیه‌ی هر نشست + سقف هر آدرس
  sameOrigin                  نوشتن از دامنه‌ی بیگانه → ۴۰۳
  Cache-Control: no-store     روی همه‌ی /api
  routes/index.js  ─▶  modules/havale/havale.routes.js
                         ├─ authenticate           کوکی → نشست → کاربر
                         ├─ requirePasswordChanged
                         ├─ requireActiveSubscription (برای نوشتن)
                         ├─ validate(schema)        Joi؛ خطا = ۴۲۲
                         └─ controller → service → repository (Prisma) → dto
  notFound, errorHandler      تنها جایی که خطا شکل می‌گیرد
```

پاسخ همیشه یک شکل دارد (`responses/apiResponse.js`):

```json
{ "success": true,  "message": null, "data": { … } }
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "…", "details": [ … ] } }
```

## ۲.۳ الگوی سرور: هسته‌ی مشترک + ماژول برای هر بازار

هر سه بازار روی **یک جدول `Listing`** با ستون `market` ذخیره می‌شوند. آنچه بین
بازارها مشترک است در **هسته** است و آنچه مخصوص یک بازار است در **ماژول همان بازار**.

```
modules/
  listing/          ← هسته: نمایش مشخصات (reveal)، رجیستری بازارها
  subscription/     ← هسته: اشتراک، سهمیه، ظرفیت
  report/ notice/   ← هسته: گزارش تخلف، اطلاعیه
  havale/           ← بازار حواله      ┐
  registration/     ← بازار ثبت‌نامی    ├─ هر کدام: routes, service, repository, dto, validator, market
  car/              ← بازار خودرو       ┘
```

قاعده‌ی مقدس: **هسته هیچ بازاری را import نمی‌کند.** هر بازار خودش را در رجیستری
معرفی می‌کند:

```js
// modules/havale/havale.market.js
registerMarket('HAVALE', {
  label: 'حواله',
  include:   { … },          // چه رابطه‌هایی برای این بازار load شود
  summarise: (row) => ({ … }), // خلاصه‌ی کارت برای میز مدیریت
  describe:  (row) => [ { label, value, icon } … ],  // ردیف‌های جزئیات
});
```

میز مدیریت و داشبورد از رجیستری می‌پرسند و هرچه بازارها گفته‌اند نشان می‌دهند —
**پنل حق ندارد بداند این فیلدها یعنی چه.** به همین دلیل افزودن بازار قطعات یعنی
یک پوشه‌ی جدید + یک خط در منو، بدون دست زدن به فایل مشترک. فصل ۵ یک بازار را
قدم‌به‌قدم می‌سازد.

## ۲.۴ الگوی پنل: حالت → رندر، یک شنونده‌ی کلیک

پنل یک SPA بدون فریم‌ورک است. سه چیز را بفهمید، بقیه از آن درمی‌آید:

1. **حالت در `state/store.js`** است؛ `setState()` کل صفحه را از نو رندر می‌کند
   (`root.innerHTML = String(page())`). به همین دلیل چیزی که کاربر در فرم تایپ
   کرده در store نمی‌رود — اجزای فرم حالتشان را در DOM نگه می‌دارند.
2. **`ui/html.js`**: تابع `html\`…\`` هر مقدار تزریق‌شده را escape می‌کند؛ فقط
   `raw()` از این قاعده مستثناست و باید در diff دیده شود.
3. **یک شنونده‌ی کلیک برای کل برنامه** در `main.js`: دکمه‌ها با `data-*`
   علامت می‌خورند و هر کلید `data-*` تازه باید در `CLICK_KEYS` ثبت شود، وگرنه در
   سکوت هیچ کاری نمی‌کند.

مسیریابی با هش است (`#search?page=2`)؛ `router.js` برای هر صفحه یک `load()`
(داده) و یک `page()` (رندر) دارد، و دو نگهبان: تغییر اجباری رمز و راهنمای اول ورود.

## ۲.۵ چیزهایی که خارج از مسیر درخواست‌اند

| کار | کجا | چطور |
|---|---|---|
| قیمت روز خودرو | `src/jobs/car-prices.js` | کرون هر ۱۵ دقیقه، دو صفحه از منبع، چهار گیت اعتبار، یک تراکنش نوشتن. پنل فقط دیتابیس را می‌خواند |
| نگه‌داری شبانه | `src/jobs/nightly.js` | آرشیو NDJSON لاگ‌ها، سپس پاک کردن با تأیید تعداد؛ پاک‌سازی نشست‌ها، کدها، پیامک‌ها، تاریخچه‌ی قیمت |
| پیامک | `modules/sms/` | درایور `log` (پیش‌فرض) یا پنل واقعی؛ هر پیام در جدول `SmsMessage` می‌ماند |
| هشدار به مالک | `utils/logger` → `modules/alert` → ربات | خطاهای ۵۰۰، خرابی قیمت، دیده‌بان |
| رمزنگاری ستون‌ها | `config/database.js` + `utils/crypto.js` | AES-256-GCM روی شماره‌ها؛ **فعلاً خاموش** (کلید خالی) — تصمیم مالک |

## ۲.۶ چرا این‌طور؟ (تصمیم‌های بزرگ)

| تصمیم | دلیل |
|---|---|
| بدون فریم‌ورک فرانت | مخاطب نمایندگی‌ها با اینترنت ضعیف‌اند؛ صفر وابستگی، صفر build، فونت محلی. کل پنل زیر ۳۰۰ کیلوبایت |
| نشست در دیتابیس، نه JWT | «یک نشست برای هر حساب» و قطع فوری نشست نیاز به حالت سمت سرور دارد؛ JWT قابل پس‌گرفتن نیست |
| کرون هاست به‌جای زمان‌بند داخل پروسه | با چند worker یک زمان‌بند داخلی چند بار اجرا می‌شد؛ کانتینر تازه برای هر اجرا یعنی حافظه‌ی نشتی هم پاک می‌شود |
| یک جدول برای هر سه بازار | «نمایش مشخصات»، گزارش، تعلیق و اطلاعیه برای همه یکی است؛ سه جدول یعنی سه کپی از همان قاعده که روزی از هم دور می‌شوند |
| فهرست بسته‌ی خودرو (کاتالوگ) | با متن آزاد، «فونیکس FX» و «Fownix FX» دو خودرو می‌شدند و فیلتر بی‌معنی می‌شد |
| ۴۲۲ برای خطای اعتبارسنجی | پنل از روی کد تصمیم می‌گیرد پیام را زیر کدام فیلد بگذارد |
