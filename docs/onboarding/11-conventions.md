# فصل ۱۱ — قراردادهای نوشتن کد

**در این فصل:** چیزهایی که اگر رعایت نشوند، کد کار می‌کند ولی پروژه کم‌کم
ناخوانا و ناامن می‌شود. کوتاه، چون بیشترشان یک خط‌اند.

---

## ۱۱.۱ زبان

| کجا | زبان |
|---|---|
| رابط کاربری، پیام‌های خطا، اسناد | فارسی — اعداد فارسی، تاریخ شمسی، «‌» نیم‌فاصله درست |
| توضیحات داخل کد، نام متغیر و تابع، پیام کامیت (یا فارسی یا انگلیسی) | انگلیسی |
| نام تست | جمله‌ی انگلیسی؛ واژه‌های محصول (حواله، خودرو) به فارسی مجاز |

متن‌های رابط در `constants/messages.js` (سرور) و داخل خودِ صفحه‌ها (پنل). متن
مشترک بازارها در `MESSAGES.LISTING`.

---

## ۱۱.۲ توضیحات کد: «چرا»، نه «چه»

این پروژه عمداً پرتوضیح است و بیشترین ارزشش همان‌جاست. توضیح خوب می‌گوید چه
اشتباهی این خط را ساخته و اگر پاکش کنید چه می‌شکند. توضیح بد کد را به انگلیسی
ترجمه می‌کند.

```js
// خوب:
// Counted from the parsed body, not Content-Length: a client can declare any
// length it likes, and a declared size over the cap must not skip the scan.

// بد:
// get body size
```

بالای هر فایل غیر بدیهی یک بلاک توضیح هست. وقتی رفتار را عوض می‌کنید، توضیح را
هم عوض کنید — توضیح کهنه بدتر از نبودنش است.

---

## ۱۱.۳ ساختار

- **بک‌اند**: ماژول = موضوع (`modules/<name>/`)، فایل‌ها به نام نقش (`x.routes.js`,
  `x.service.js`, …). چیزی که به هیچ موضوعی تعلق ندارد در `utils/`، `middlewares/`،
  `constants/`. CommonJS، `async/await`، بدون کلاس مگر خطاها.
- **پنل**: ES Modules، یک فایل برای هر صفحه یا جزء UI. `pages/agent/x.js` هر دو
  `loadX()` و `xPage()` را export می‌کند.
- **بدون وابستگی تازه بی‌دلیل.** پنل صفر وابستگی است و باید بماند. بک‌اند برای
  هر بسته‌ی جدید یک جمله «چرا این و نه چند خط کد خودمان» می‌خواهد.
- **بدون کد مرده** و بدون پوشه‌ی خالی «برای آینده».

---

## ۱۱.۴ API

- پاسخ همیشه `{ success, data | error }`. کد خطا ماشین‌خوان از `errorCodes.js`.
- اعتبارسنجی → **۴۲۲** با `details[{field, message}]`. ۴۰۰ فقط برای «درخواست
  بی‌معنی» (مثلاً محتوای فایل با نوعش نمی‌خواند).
- «مال کسی دیگر» → ۴۰۴، نه ۴۰۳.
- صفحه‌بندی: `page`/`limit`، `MAX_PAGE = 50`، پاسخ `{ items, total, page }`.
- فهرست در query با کاما (`brandIds=a,b`) و اعتبارسنجی کلمه‌به‌کلمه (`utils/queryList.js`).
- پول `BigInt` تومان در DB، عدد در JSON.
- زمان ISO در JSON؛ «روز» یعنی روز تهران (`utils/time.js`).

## ۱۱.۵ پنل

- `html\`\`` همه‌جا؛ `raw()` قابل دفاع در diff.
- کلیک با `data-*` + ثبت در `CLICK_KEYS`.
- حالت فرم در DOM؛ حالت صفحه در store.
- هر فیلد `id`/`name`؛ اعداد فارسی؛ پول از `moneyInput`؛ تاریخ از `dateInput`.
- هیچ نام برند/منبع بیرونی در متن.
- موبایل‌اول: هر صفحه‌ی جدید را در ۳۹۰px هم ببینید.

---

## ۱۱.۶ گیت

- **یک شاخه**: نامش در `CLAUDE.md` و در `deploy/update.sh` پین شده. مالک از همان
  دیپلوی می‌کند. شاخه‌ی دیگری push نکنید مگر با هماهنگی.
- پیام کامیت: عنوان یک جمله‌ی کامل درباره‌ی **چه و چرا** («Serialise the reveal
  spend per viewer so racing requests cannot double-spend»)، بدنه اگر لازم بود.
  فارسی هم پذیرفته است. بدون پیشوندهای `feat:`.
- هر کامیت سبز: lint + `RUN_E2E=1 npm test`. قبل از push: اسموک.
- تغییر schema → مایگریشن در همان کامیت. تغییر قاعده‌ی محصول یا معماری →
  `docs/handover.md` در همان کامیت (قاعده‌ی بالای آن فایل).
- هرگز: `.env`، `.htpasswd`، گزارش امنیتی، رمز، نام مالک.

## ۱۱.۷ ابزار

```bash
cd backend
npm run lint          # eslint (تنظیمات در .eslintrc)
npm run lint:fix
npm run format        # prettier روی js/json/md
```

پنل lint ندارد؛ همان قاعده‌های ESLint بک‌اند (بدون `var`، `const` پیش‌فرض، بدون
متغیر بی‌استفاده) را دستی رعایت کنید.
