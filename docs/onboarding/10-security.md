# فصل ۱۰ — امنیت

**در این فصل:** قاعده‌های غیرقابل‌مذاکره، لایه‌های دفاعی که وجود دارند و کجا
هستند، و چطور یک تغییر را بدون باز کردن سوراخ تازه بنویسید. گزارش کامل آخرین
بازبینی در [`docs/security-audit.md`](../security-audit.md).

---

## ۱۰.۱ قاعده‌های مالک — بدون استثنا

1. **هیچ رمز، کلید API یا رازی در چت، کامیت، سند یا لاگ نوشته نمی‌شود.** خروجی
   `.env` را هیچ‌جا paste نکنید؛ در دستورها با `…` جایگزین کنید.
2. **نام کاربری حساب مالک (`OWNER`) هیچ‌جا نوشته نمی‌شود.** نه در کد، نه seed، نه
   تست، نه سند، نه گفتگو. `create-owner.js` عمداً تعاملی است.
3. توسعه فقط روی شاخه‌ی توافق‌شده (`CLAUDE.md`)؛ دیپلوی فقط توسط مالک.
4. `SEED_DEMO`/`ALLOW_DEMO_SEED` پیش از اولین نمایندگی واقعی `false`.
5. نام منبع «قیمت روز» در رابط نمی‌آید.

## ۱۰.۲ لایه‌ها — چه چیزی کجا محافظت می‌شود

| تهدید | دفاع | کجا |
|---|---|---|
| نشت شماره‌ی تماس (اصلی‌ترین ریسک کسب‌وکار) | فقط dtoها شماره را می‌خوانند؛ کارت عمومی بدون متن تایپی؛ عکس پشت مجوز؛ `textGuard`؛ `textLeak.test`؛ اسموک کل سند را می‌گردد | `*.dto.js`, `utils/textGuard.js` |
| XSS | `html\`\`` escape پیش‌فرض؛ `raw()` فقط ثابت؛ `safeUrl()`؛ CSP `script-src 'self'` بدون inline | `ui/html.js`, `deploy/nginx/security-headers.inc` |
| CSRF | کوکی `SameSite=Strict` + میان‌افزار `sameOrigin` (Origin/Referer بیگانه → ۴۰۳) | `middlewares/sameOrigin.js` |
| SQL injection | Prisma با پارامتر؛ صفر `$queryRawUnsafe` | همه‌جا |
| دزدی نشست | توکن تصادفی، فقط هش در DB، `httpOnly; Secure`، یک نشست برای هر نمایندگی، قطع سمت سرور | `modules/auth` |
| حدس رمز | rate limit ورود (۱۰ خطا/۱۵ دقیقه به ازای آدرس+نام)، قفل حساب (۵ از یک آدرس، ۲۵ از هر جا)، هش ساختگی هم‌زمان | `rateLimiter.js`, `auth.service.js` |
| سیل درخواست | سهمیه‌ی هر نشست + سقف هر آدرس؛ `Content-Length` ۱ مگابایت؛ آپلود ۵ مگابایت × ۳-۶ | `rateLimiter.js`, `uploads.js` |
| دور زدن سهمیه با هم‌زمانی | قفل مشورتی به ازای بیننده / مادر / گزارش‌دهنده | `utils/serialize.js` |
| فایل مخرب | نوع از **بایت‌های واقعی** فایل؛ نام تصادفی؛ سرو با `nosniff` و پشت مجوز | `utils/uploads.js` |
| افزایش دسترسی کارمند | `requirePermission` روی هر مسیر مدیریت؛ مسیرهای `/admin/agents/*` فقط روی نقش AGENT؛ کارمندان فقط از `staff.service` با قاعده‌ی مالک | `middlewares/auth.js`, `admin/` |
| clickjacking، sniff، referrer | `X-Frame-Options DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP, HSTS | `security-headers.inc` |
| کش پاسخ‌های خصوصی | `Cache-Control: no-store` روی `/api` | `app.js` |
| اسکن و نفوذ | `threatDetect` ثبت می‌کند (نمی‌بندد)؛ تله‌ی اسکنر nginx؛ لاگ امنیتی پنل مالک؛ بستن دستی آدرس | `threatDetect.js`, `site.inc`, `modules/security` |
| دامپ لو رفته | رمزنگاری ستون‌ها (AES-GCM) — **فعلاً خاموش به تصمیم مالک** | `config/database.js`, `utils/crypto.js` |
| زیرساخت | فقط nginx پورت دارد؛ کاربر غیر-root؛ `no-new-privileges`؛ `cap_drop ALL` روی API؛ ufw؛ fail2ban؛ SSH فقط با کلید | `docker-compose.yml`, `deployment.md`, `preflight.d/` |

## ۱۰.۳ وقتی کد می‌نویسید

**سرور**

- مسیر جدید: `authenticate` + `requirePasswordChanged` + نقش/مجوز + `validate()`.
  هیچ مسیری بدون اسکیما.
- هر جا داده‌ی «مال کسی» می‌خوانید، با `requireOwn` یا فیلتر مالک در **کوئری** —
  و پاسخِ نبودن، ۴۰۴ باشد نه ۴۰۳.
- شماره‌ی تماس فقط در dto. اگر `x.coordinatorPhone` را جای دیگری نوشتید، اسکن
  امنیتی قرمز می‌شود — درست است.
- سهمیه یا سقف جدید؟ شمارش و نوشتن را زیر `serialized(key, tx => …)` بگذارید.
- لاگ: هرگز شماره‌ی کامل، رمز، توکن. `maskPhone()` برای شماره.
- تغییر حالت با GET ممنوع.
- خطای ۵۰۰ یعنی باگ؛ هر ورودی بدِ قابل پیش‌بینی باید ۴xx برگردد.

**پنل**

- `html\`\``، نه چسباندن رشته. `raw()` فقط برای ثابت‌ها.
- `href`/`src` از سرور → `safeUrl()`.
- هیچ تصمیم مجوزی در پنل؛ `can()` را از سرور می‌گیرد و فقط برای نمایش/عدم نمایش.
- هیچ داده‌ای در `localStorage`.

**زیرساخت**

- `location` جدید در nginx که `add_header` دارد → `include security-headers.inc`.
- فایل جدید در `frontend/` = قابل دانلود از اینترنت. چیزی که مال سایت نیست را
  آن‌جا نگذارید (اسکریپت‌ها به `docs/` یا `deploy/`).
- متغیر محیطی جدید: در `config/index.js` با پیش‌فرض، در `.env.example` با توضیح.

## ۱۰.۴ تصمیم‌های امنیتی که به تعویق افتاده‌اند

این‌ها بررسی شده‌اند و مالک آگاهانه گفته «فعلاً نه». پیشنهاد دوباره فقط وقتی
شرایط عوض شود:

| مورد | وضعیت | چه وقت دوباره مطرح شود |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | خالی — شماره‌ها متن ساده | پیش از اولین داده‌ی واقعی (launch-checklist) |
| بکاپ خارج از سرور | نیست | همان |
| رمز کردن آرشیو بکاپ | نیست (`.env` کنار دامپ) | همراه با کلید |
| Adminer فقط روی loopback + تونل SSH | روی اینترنت پشت TLS و دو رمز | هر وقت مالک بخواهد |
| تگ امضاشده برای دیپلوی | شاخه، بدون امضا؛ دیپلوی دستی | پیش از توسعه‌دهنده‌ی دوم |

## ۱۰.۵ اگر حادثه‌ای رخ داد

1. **نشت شماره** (اسموک قرمز، گزارش نمایندگی): مسیر مربوط را از nginx ببندید یا
   API را پایین بیاورید؛ `ContactReveal` و `ActivityLog` را برای بازه نگاه کنید؛
   dto مقصر را ببندید؛ تست بنویسید؛ مالک را مطلع کنید.
2. **حساب مدیر لو رفته**: پنل مالک ← کارمندان ← ریست رمز و خروج اجباری؛ لاگ کارها
   برای آن حساب؛ `SecurityEvent` برای آدرس.
3. **سرور لو رفته**: فرض کنید `.env` رفته — `SESSION_SECRET`، رمز DB، توکن ربات
   عوض شوند؛ بازگردانی از بکاپ روی سرور تازه (`RESTORE.md` داخل آرشیو).
