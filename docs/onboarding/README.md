# دفترچه‌ی فنی فرانوکار — راهنمای توسعه‌دهنده‌ی تازه‌وارد

این پوشه برای روزی نوشته شده که یک توسعه‌دهنده‌ی جدید بدون هیچ سابقه‌ای پروژه را
تحویل می‌گیرد. اگر همه‌ی فصل‌ها را به ترتیب بخوانید — حدود دو ساعت — می‌دانید محصول
چیست، کد کجاست، چطور اجرا و تست و دیپلوی می‌شود، و کدام قاعده‌ها را نباید شکست.

هر فصل مستقل است و با یک خط «در این فصل» شروع می‌شود. جایی که سند مفصل‌تری وجود
دارد (مثلاً راه‌اندازی سرور)، این‌جا خلاصه می‌آید و به آن سند لینک می‌شود.

## روز اول شما — فهرست کار

1. فصل ۱ و ۲ را بخوانید (۳۰ دقیقه).
2. فصل ۴ را قدم‌به‌قدم اجرا کنید تا پنل روی `http://localhost:5173` بالا بیاید.
3. با حساب نمونه‌ی `zagros` وارد شوید، راهنمای داخل پنل را ورق بزنید، یک حواله ثبت
   کنید و یک «نمایش مشخصات» انجام دهید — این چرخه‌ی اصلی محصول است.
4. فصل ۹ را اجرا کنید: تست‌های بک‌اند و اسموک مرورگری باید سبز باشند. این
   «خط پایه»ی شماست؛ هر تغییری که آن را قرمز کند مقصر است.
5. فصل ۳ را کنار دست نگه دارید و فصل ۵ یا ۶ را بسته به کارتان بخوانید.
6. قبل از اولین کامیت، فصل ۱۰ و ۱۱ را بخوانید.

## چند قاعده که همین اول باید بدانید

- **هیچ رمز، کلید یا رازی** در کد، سند، کامیت یا چت نوشته نمی‌شود. `.env` هرگز کامیت نمی‌شود.
- **نام کاربری حساب مالک** (نقش `OWNER`) هیچ‌جا نوشته نمی‌شود — نه در کد، نه در سند، نه در گفتگو.
- **مالک خودش دیپلوی می‌کند.** توسعه‌دهنده به سرور تولید دسترسی ندارد؛ کد را روی شاخه‌ی
  توافق‌شده push می‌کنید و مالک `update.sh` را اجرا می‌کند.
- رابط کاربری و اسناد **فارسی**؛ توضیحات داخل کد **انگلیسی** و همیشه درباره‌ی «چرا»، نه «چه».
- هر کامیت باید سوئیت تست و lint را سبز نگه دارد (فصل ۹).
