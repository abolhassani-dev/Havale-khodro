# بازرسی امنیتی

```bash
node security/audit.js                                   # فقط کد
node security/audit.js --live https://feranocar.com \
     --user alborz --pass '…'                            # کد + حمله‌ی واقعی
node security/audit.js --fix                             # اصلاح خودکارِ موارد امن
```

خروجی روی صفحه، و گزارش کامل در `security/last-report.json`.
اگر چیزی **بحرانی** یا **مهم** پیدا شود، اسکریپت با کد خطا تمام می‌شود — پس می‌شود آن را
در CI گذاشت.

## دو نوع بررسی، و دومی مهم‌تر است

**بررسی کد** — دنبال الگوهایی می‌گردد که آسیب‌پذیری می‌سازند: `innerHTML` روی داده‌ی کاربر،
SQL ساخته‌شده با چسباندن رشته، کوکی بدون `httpOnly`، رازِ کامیت‌شده در مخزن، پورت باز
دیتابیس، هدرهای امنیتی غایب.

**حمله‌ی واقعی** (`--live`) — به یک نسخه‌ی در حال اجرا **واقعاً حمله می‌کند**: پیلود تزریق
می‌فرستد، درخواست جعلی بین‌سایتی می‌زند، شماره‌ای را می‌خواهد که پولش را نداده، و با یک
حساب نمایندگی سراغ مسیرهای مدیریت می‌رود. بررسی کد فقط می‌گوید کد *به نظر* درست است؛
این می‌گوید سیستم *واقعاً* درست رفتار می‌کند.

## چه چیزهایی را می‌گیرد

| دسته | نمونه |
|---|---|
| XSS | سینک‌های خطرناک، و اینکه تابع escape واقعاً هر پنج کاراکتر را escape کند |
| SQL injection | `$queryRawUnsafe`، SQL ساخته‌شده با `+` — و در حالت live، چهار پیلود واقعی |
| CSRF | فلگ `SameSite`، و مسیرهای تغییردهنده‌ای که با GET سرو شده‌اند |
| دزدیدن توکن | `httpOnly`، `Secure`، و اینکه توکن در بدنه‌ی پاسخ نباشد |
| Brute force | وجود محدودکننده‌ی اختصاصی ورود — و در حالت live، ۱۵ تلاش پشت‌سرهم |
| ماسکینگ تماس | مهم‌ترین قاعده‌ی این کسب‌وکار: هیچ شماره‌ای بدون reveal ثبت‌شده سریالایز نشود |
| رازها | کلید خصوصی، توکن، و اینکه `.env` و `.htpasswd` در `.gitignore` باشند |
| استقرار | پورت باز دیتابیس/API/پنل، هدرهای nginx، مجوز فایل رمز پنل، روشن بودن TLS |
| وابستگی‌ها | `npm audit` روی advisoryهای high و critical |

## درباره‌ی `--fix`

فقط چیزهایی را خودکار اصلاح می‌کند که **یک جواب درست دارند و برگشت‌پذیرند** — مجوز فایل،
اضافه کردن مسیر به `.gitignore`. هر چیزی که جوابش به قصد شما بستگی دارد، فقط گزارش
می‌شود و دست نخورده می‌ماند.

این عمدی است. ابزاری که بی‌صدا منطق دسترسی را بازنویسی کند، خودش از آن یافته خطرناک‌تر
است: تغییرش را کسی مرور نمی‌کند و نتیجه‌اش سیستمی است که فکر می‌کنید امن شده.

## دو نکته‌ی عملی

- تست brute-force **سهمیه‌ی ورود همان IP را مصرف می‌کند**. اگر بلافاصله دوباره اجرا کنید،
  گزارش می‌گوید ورود rate-limited است — این خودش نشانه‌ی سالم بودن سیستم است، نه خرابی.
- اجرای `--live` روی سرور واقعی چند رکورد در لاگ فعالیت می‌سازد (ورود، نمایش مشخصات).
  اگر نمی‌خواهید، با حساب دمو اجرایش کنید نه با حساب واقعی.
