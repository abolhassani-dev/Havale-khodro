۱۱ / ۱۳دسته بدون یافته‌ی باز
وضعیت: قابل‌قبول برای لانچ آزمایشی

دو یافته‌ی واقعی پیدا و همان‌جا رفع شد. هیچ آسیب‌پذیری بحرانی باز نمانده. دو دسته‌ی باقی‌مانده (آپلود فایل، ۲FA) در دامنه‌ی این فاز نیستند.

✓ ۱۱ سالم ◑ ۲ رفع‌شده ✕ ۰ باز
01جمع‌آوری اطلاعات و افشای فریم‌ورکسالم▾
✓
هدر Server نسخه‌ی وب‌سرور را لو نمی‌دهد
هیچ بنر نسخه‌ای برنمی‌گردد؛ server_tokens off در nginx.
✓
هدر X-Powered-By حذف شده
Helmet آن را می‌بندد — فریم‌ورک بک‌اند از پاسخ قابل تشخیص نیست.
✓
فایل‌های زیرساخت سرو نمی‌شوند
.env، .git/config، docker-compose.yml همه ۴۰۴ — nginx فقط frontend/ را سرو می‌کند.
02پیکربندی و متدهای HTTPسالم▾
✓
متدهای خطرناک رد می‌شوند
PUT، DELETE، PATCH روی مسیر فقط‌خواندنی ۴۰۴؛ TRACE هم سمت کلاینت و هم سمت سرور بسته است (دفاع XST).
✓
HSTS فعال
دو سال، فقط بعد از تثبیت HTTPS — مرورگر دیگر HTTP را امتحان نمی‌کند.
✓
پنل‌های مدیریتی پشت احراز هویت
دیتابیس (Adminer) پشت سه لایه‌ی رمز؛ پورت دیتابیس و API اصلاً منتشر نمی‌شوند.
03مدیریت هویت و احراز هویتسالم▾
✓
شمارش حساب ممکن نیست
رمز اشتباه و کاربر ناموجود پاسخ کاملاً یکسان می‌دهند — نمی‌شود فهمید کدام نام کاربری وجود دارد.
✓
قفل‌شدن بعد از تلاش ناموفق
۱۰ حدس اشتباه در ۱۵ دقیقه؛ ورودهای موفق شمرده نمی‌شوند تا کاربر واقعی قفل نشود.
✓
تغییر رمز، رمز فعلی را می‌خواهد
و همه‌ی نشست‌های دیگر را می‌بندد؛ ورود اول تغییر اجباری رمز دارد.
✓
رمزها فقط hash (bcrypt) ذخیره می‌شوند
هرگز متن ساده؛ hash در هیچ پاسخی سریالایز نمی‌شود.
05کنترل دسترسی و IDORسالم▾
✓
دسترسی عمودی: نماینده به مسیرهای مدیریت نمی‌رسد
هر شش مسیر آزموده‌شده (admin/agents، settings، admin/activity و…) با ۴۰۳ رد شدند.
✓
دسترسی افقی: یک نمایندگی نمی‌تواند آگهی دیگری را دست بزند
تلاش برای DELETE/PATCH روی آگهی نمایندگی دیگر → ۴۰۴. شناسه‌ی آگهی راه دور زدن مالکیت نیست.
✓
اطلاعات تماس هرگز بدون reveal ثبت‌شده لو نمی‌رود
مهم‌ترین قاعده‌ی کسب‌وکار؛ ماسکینگ در لایه‌ی سریال‌سازی، نه رابط کاربری.
06مدیریت نشستسالم▾
✓
کوکی نشست: HttpOnly + SameSite=Strict + Secure
اسکریپت تزریقی نمی‌تواند توکن را بخواند؛ SameSite=Strict همان دفاع CSRF است.
✓
Session fixation بسته
با هر ورود نشست تازه صادر می‌شود؛ توکن قبلی معتبر نمی‌ماند.
✓
توکن فقط به‌صورت hash در دیتابیس
نشست‌ها DB-backed و قابل ابطال‌اند — تک‌نشستی و خروج اجباری از همین‌جاست.
07اعتبارسنجی ورودی — XSS و تزریقسالم▾
✓
SQL Injection ممکن نیست
هر کوئری از Prisma با پارامتر بایند رد می‌شود؛ چهار payload واقعی (' OR '1'='1، DROP TABLE، UNION SELECT، URL-encoded) بی‌اثر.
✓
XSS مسدود
همه‌ی خروجی از تابع escape رد می‌شود (۵ کاراکتر)؛ ورودی به‌صورت HTML خام برنمی‌گردد؛ CSP بدون unsafe-inline در script-src.
✓
اعتبارسنجی سمت سرور با Joi
هر ورودی قبل از رسیدن به منطق، schema می‌خورد — نوع، طول و مقدار.
08مدیریت خطارفع شد▾
◑
بدنه‌ی JSON بدشکل حالا 400 است، نه 500
قبلاً پیام خودِ body-parser («Expected property name…») برمی‌گشت که فریم‌ورک را لو می‌داد و خطای کاربر را باگ سرور جا می‌زد. حالا پیام فارسی تمیز، بدون افشای درونیات.
قبلاً: 500 + پیام پارسر
◑
بدنه‌ی بیش از حد بزرگ حالا 413 است
قبلاً ۵۰۰ می‌داد و لاگ خطا را پر می‌کرد. دو تست دائمی برای هر دو اضافه شد.
قبلاً: 500
✓
خطای ۵۰۰ هیچ stack trace یا پیام دیتابیس لو نمی‌دهد
در تولید پیام عمومی «Something went wrong»؛ جزئیات فقط در لاگ سمت سرور.
09رمزنگاری و TLSسالم▾
✓
TLS 1.2/1.3، گواهی معتبر Let's Encrypt
تمدید خودکار فعال و تست‌شده؛ بازرسی امنیتی تاریخ انقضا را پایش می‌کند.
✓
همه‌ی ترافیک HTTP به HTTPS ریدایرکت می‌شود
به‌جز مسیر ACME (برای تمدید) و health (برای healthcheck) — با دلیل مستند.
✓
رمزنگاری اختیاری شماره‌ها در دیتابیس
AES-256-GCM با کلید در .env؛ در برابر دامپ دزدیده‌شده. قابل روشن‌کردن بدون تغییر رفتار برنامه.
10منطق کسب‌وکارسالم▾
✓
سقف نمایش مشخصات دور زدنی نیست
شمارش سمت سرور با روز تقویمی تهران؛ باز کردن دوباره‌ی همان آگهی رایگان و ثبت‌شده.
✓
مبلغ پرداختی نمی‌تواند از مبلغ کل بیشتر باشد
اعتبارسنجی منطقی در سطح schema، نه فقط رابط.
✓
اشتراک منقضی، هویت و تماس را می‌بندد
بررسی روی وضعیت فعلی، نه خرید گذشته — reveal ماه قبل با انقضا بی‌اثر می‌شود.
11سمت کلاینت — Clickjacking و CORSسالم▾
✓
Clickjacking بسته
X-Frame-Options: DENY و frame-ancestors 'none' در CSP — پنل داخل iframe کسی باز نمی‌شود.
✓
CORS مبدأ ناشناس را بازتاب نمی‌دهد
فقط مبدأهای پیکربندی‌شده؛ Origin: evil.example پذیرفته نشد.
✓
بدون ریدایرکت باز (Open Redirect)
مسیریابی داخلی هش‌محور است؛ مقصد از ورودی کاربر ساخته نمی‌شود.
12محدودسازی نرخ و منع سوءاستفادهسالم▾
✓
Rate limiting روی همه‌ی API
کلید بر اساس نشست (نه فقط IP) تا کاربران پشت یک اینترنت مشترک قفل نشوند؛ مسیر health مستثنا.
✓
ورود، محدودیت سخت‌گیرانه‌ی خودش را دارد
کلید شامل نام کاربری تا حمله به یک حساب، بقیه را قفل نکند؛ فقط تلاش ناموفق شمرده می‌شود.
13خارج از دامنه‌ی این فازN/A▾
—
آپلود فایل مخرب
این سامانه هیچ آپلود فایلی ندارد — سطح حمله‌اش وجود ندارد. اگر در فاز بعد اضافه شد، باید جداگانه آزموده شود.
—
۲FA / OTP
پنل پیامکی هنوز وصل نیست؛ کد دوعاملی به‌صورت ماژولار آماده است ولی خاموش. آزمونش موقع فعال‌سازی.
—
EXIF / SPF / Subdomain Takeover
اولی (بدون آپلود عکس) موضوعیت ندارد؛ دومی و سومی سطح DNS/ایمیل‌اند و بعد از راه‌اندازی ایمیل سازمانی بررسی می‌شوند.

روش کار — چرا این گزارش قابل اتکاست
